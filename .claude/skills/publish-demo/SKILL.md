# Publish the demo and refresh its links

One command's worth of work: ship `apps/demo` to Pages, screenshot the live site,
and push those screenshots plus the demo link everywhere the project is described.

## Where things live

| Surface | Location |
| --- | --- |
| Demo (deployed) | <https://kucukkanat.github.io/lfm-encoders/> |
| Pages workflow | `.github/workflows/pages.yml` (push to `main` touching `apps/demo/**` or `packages/**`) |
| Screenshots | `docs/screenshots/*.png`, committed |
| GitHub repo | `kucukkanat/lfm-encoders` — description + homepage |
| Root README | `README.md` — "Live demo" section |
| HF model cards | generated by `tools/export/lfm_export/publish.py` (`CARD` template) |

The three Hub repos:

- `kucukkanat/LFM2.5-Encoder-350M-ONNX`
- `kucukkanat/LFM2.5-Encoder-350M-Prompt-Router-ONNX`
- `kucukkanat/LFM2.5-Encoder-350M-Policy-Linter-ONNX`

## Steps

### 1. Ship it

```bash
bun run check && bun run typecheck && bun test packages/*/test/unit
git add -A && git commit -m "…" && git push origin main
gh run watch "$(gh run list --limit 1 --json databaseId -q '.[0].databaseId')" --exit-status
```

The workflow runs lint, typecheck and unit tests before deploying. Integration
tests are skipped in CI on purpose — they need multi-gigabyte weights.

### 2. Screenshot the live site

Drive <https://kucukkanat.github.io/lfm-encoders/> with the browser tools. Three
shots, one per tab, into `docs/screenshots/`:

| File | Tab | Setup |
| --- | --- | --- |
| `prompt-routing.png` | Prompt routing | default text + categories |
| `policy-linting.png` | Policy linting | default draft + policy, threshold 0.50 |
| `fill-mask.png` | Fill-mask | `The capital of France is <|mask|>.` |

Details that matter:

- **Switch precision to `q8` first.** The page defaults to `fp32`, which is a
  1.4 GB download over the network and will look broken while it streams.
- Wait for the status bar to read `forward pass …ms` before capturing — that is
  the signal inference actually completed.
- Capture with `zoom` over roughly `[405, 12, 1165, 545]` rather than a full
  screenshot; the page is wider than its content and a raw shot is mostly empty.
- Each tab downloads a *different* model. Fill-mask is a separate 424 MB fetch
  and is the slow one.

### 3. Update the surfaces

**GitHub repo metadata:**

```bash
gh repo edit kucukkanat/lfm-encoders \
  --homepage "https://kucukkanat.github.io/lfm-encoders/" \
  --description "…mention the live demo…"
```

**Root README** — keep the "Live demo" section near the top, with the link and
the routing + linting screenshots.

**HF model cards** — edit the `CARD` template in
`tools/export/lfm_export/publish.py`, then regenerate and push *cards only*:

```bash
bun run publish:hub -- --cards-only
```

`--cards-only` re-uploads `README.md` and screenshots without re-sending
gigabytes of unchanged weights. Requires `hf auth login` with a write token.

## Rules

- **Never handle the HF token.** If `hf auth whoami` fails, stop and ask the user
  to run `hf auth login` themselves. Do not read, type, or echo a token value.
- **Screenshots must come from the deployed site**, not `bun run dev` — the point
  is to show what a visitor actually sees, including Hub-sourced weights.
- **Do not re-upload weights** unless they changed. Cards and screenshots are
  small; the `.onnx` files are not.
- Verify the live site computes correctly before screenshotting: routing on the
  default input should give **billing and payments ≈ 83.8%**. Anything else means
  something regressed — investigate rather than screenshot it.
- The deployed page is **not** cross-origin isolated (Pages cannot set COOP/COEP),
  so onnxruntime runs single-threaded WASM and is slower than local dev. That is
  expected; do not "fix" it by chasing headers.
